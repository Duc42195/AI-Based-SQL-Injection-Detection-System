\begin{abstract}
SQL Injection (SQLi) remains a damaging web application vulnerability. Signature-based Web Application Firewalls (WAFs) struggle with obfuscated payloads and previously unseen attacks. This paper presents a multi-branch artificial intelligence system for SQLi detection. We position the system at the database proxy to inspect the final SQL statement after application construction but before database execution. The architecture combines a supervised multi-class classifier (Branch 1) and a query-level anomaly detector (Branch 2). Branch 2 trains exclusively on benign traffic. We introduce the Session Correlator to catch blind and multi-step attacks. This mechanism reuses signals from both branches without additional training. The evaluation combines four public datasets spanning structurally distinct traffic; a leave-one-out ablation confirms each source is necessary, since dropping any one leaves its own held-out benign traffic with a 65-80 percent false-positive rate. Branch 1 (DistilBERT) reaches a 0.9699 F1-macro across six SQLi categories, including a real stacked-query class previously represented only by synthetic templates, chosen over a TF-IDF plus Logistic Regression baseline for markedly better accuracy on the two hardest classes at a latency that remains real-time-compatible. Branch 2 uses Local Outlier Factor (LOF) to attain a 0.915 Area Under the Curve (AUC), detecting 78.4 percent of anomalous queries at a 5.3 percent false-positive rate (FPR). A zero-day study shows supervised classification remains robust for distinctive attacks but misses Boolean-blind payloads at an 87 percent rate. The anomaly branch independently recovers most of these on structural grounds alone. The Session Correlator recovers residual cases on a held-out set of self-generated attack sessions with zero observed false positives. We report this as preliminary evidence pending validation on independently-captured attacker traffic. Finally, we evaluate an offline continual-learning loop using drift monitoring and a review queue to surface a new class and trigger automatic retraining; a validation gate promotes the resulting major-bump model directly, then correctly rejects a subsequent minor-bump candidate with higher F1 but higher FPR before it reaches shadow, evidence the gate weighs more than a single metric. These results quantify the limits of query-level detection and motivate session-level correlation and disciplined retraining as low-cost mitigations.
\end{abstract}

\section{Introduction}
Web applications store increasingly sensitive data, making their back-end databases a persistent target. SQL Injection (SQLi), in which unsanitized user input is concatenated into a SQL statement, remains one of the oldest and most severe such threats, ranked among the OWASP Top 10 web application risks \cite{b12}. Successful exploitation can disclose, alter, or destroy data and escalate privileges. Although Web Application Firewalls (WAFs) are widely deployed, rule-based defenses depend on predefined signatures; obfuscated payloads and zero-day techniques bypass them, while overly strict rules raise the false-positive rate (FPR) on legitimate traffic.

Machine learning (ML) and deep learning have emerged as promising alternatives because they learn attack patterns from data rather than from hand-written rules \cite{b1,b2,b3}. However, most published AI-based SQLi detectors classify a \emph{single} query in isolation. This is a structural limitation: Boolean-blind and time-blind SQLi, and query-splitting attacks, distribute their malicious intent across many individually innocuous-looking queries within one session. Their signal only becomes visible when a sequence of related queries is analyzed together.

This paper describes a multi-branch AI system that performs SQLi detection at the \emph{database proxy}, inspecting the fully-built SQL statement before it reaches the database server. Two query-level branches, a supervised multi-class classifier and a benign-only anomaly detector, feed a session-level correlation mechanism that catches blind and multi-step attacks neither branch sees alone. On a combined public dataset, the system reaches an F1-macro of 0.9699 for query-level classification and an AUC of 0.915 for anomaly detection, and a leave-one-out study shows the two branches together recover most attacks that either one misses individually. The contributions of this paper are:

\begin{itemize}
\item A multi-branch detector architecture combining a supervised multi-class classifier (Branch~1) and a benign-only anomaly detector (Branch~2) under a single decision policy, with a session-level correlation mechanism (the Session Correlator) that reuses both branches' existing signals, with no additional training, to catch blind and multi-step SQLi; evaluated with a mandatory ablation over its two constituent checks.
\item A leave-one-out \emph{zero-day} study that quantifies, per attack category, how far each branch generalizes to an attack type it never saw during training, and what this implies for the value of the anomaly branch.
\item An offline evaluation of a continual-learning loop - drift monitoring, a threshold-triggered review queue, and a validation gate with a shadow stage - using a real held-out attack class, with an ablation isolating the retrain gain to the class itself rather than to added data volume.
\end{itemize}

The remainder of the paper reviews related work (Section~\ref{sec:related}), describes the proposed system (Section~\ref{sec:system}) and the experimental setup (Section~\ref{sec:setup}), reports results (Section~\ref{sec:results}), discusses limitations (Section~\ref{sec:discussion}), and concludes (Section~\ref{sec:conclusion}).

\section{Related Work}\label{sec:related}
Traditional SQLi defenses rely on input validation, parameterized queries, and rule-based WAFs such as ModSecurity with the OWASP Core Rule Set \cite{b13}. These are fast, interpretable for known attacks, and need no training data; their weakness is the flip side of that same strength, since a fixed rule set cannot anticipate a payload it has never seen, so obfuscated or novel injections bypass it while overly strict rules raise false positives on legitimate traffic \cite{b1,b13}. This trade-off, not a failure specific to any one rule set, is what motivates learning-based detection below.

ML-based detectors extract features from queries, including bag-of-words, Term Frequency-Inverse Document Frequency (TF-IDF), or character/word $n$-grams, and train classifiers such as SVM, Random Forest, or gradient-boosted trees \cite{b2}. Deep models remove the need for handcrafted features. CNNs capture local token patterns \cite{b3}, while recurrent models (LSTM/GRU) and Transformer-based encoders such as DistilBERT model longer-range structure \cite{b5,b6,b7,b8}. For unseen attacks, anomaly and ensemble approaches have been proposed, including autoencoder/LSTM/GRU ensembles for zero-day web attacks \cite{b4}. Classic one-class methods, including Isolation Forest \cite{b9} and One-Class SVM \cite{b10}, model the support of the benign distribution and flag deviations, and adversarial tools such as WAF-A-MoLE \cite{b11} expose the fragility of detectors under deliberate evasion. Recent work continues to report competitive results from classical ML with careful feature selection \cite{b14,b15}, alongside the deep-learning direction this paper also pursues.

Across this literature, detection is predominantly \emph{query-level}, issuing a verdict per query. Session-level modeling, which is required to expose blind SQLi spread over many requests, is comparatively underexplored. Our work targets that gap while grounding the design in a measured evaluation of the two query-level branches it builds on.

\section{Proposed System}\label{sec:system}

\subsection{System Placement: The Database Proxy}
The detector is placed at ``Position~B'': it receives the SQL statement after the application has finished constructing it but before the statement reaches the database. Inspecting the final statement (rather than raw HTTP input) removes ambiguity introduced by application-layer transformations and yields a canonical view of what will actually execute. Fig.~\ref{fig:arch} shows the overall flow: each query is canonicalized and scored by Branch~1 and Branch~2; the Session Correlator correlates both branches' signals over a whole session; the decision engine emits ALLOW/BLOCK/OVERKILL. Algorithm~\ref{alg:detect} summarizes the per-query decision.

\begin{algorithm}[htbp]
\footnotesize
\caption{Multi-branch detection at Position B (per query)}
\label{alg:detect}
\begin{algorithmic}[1]
\REQUIRE query $q$, models $B_1,B_2$, correlator $S$
\STATE $q_c \leftarrow \text{canonicalize}(q)$
\STATE $(p, y_1) \leftarrow B_1.\text{predict}(q_c)$ \COMMENT{$p = 1 - P(\text{normal})$}
\STATE $s \leftarrow B_2.\text{score}(q_c)$
\STATE $is\_sqli \leftarrow (p \geq 0.5)$; $is\_anom \leftarrow (s > \tau_q)$
\STATE \textbf{if} $S.\text{is\_ready}$ \textbf{and} $S.\text{score\_session}([q])$ \textbf{then} \textbf{return} BLOCK
\STATE \textbf{if} $is\_sqli$ \textbf{then} \textbf{return} BLOCK
\STATE \textbf{if} $\neg is\_sqli \land is\_anom$ \textbf{then} \textbf{return} OVERKILL
\STATE \textbf{return} ALLOW
\end{algorithmic}
\end{algorithm}

\subsection{Canonicalization}
To reduce syntactic evasion, each statement is normalized before feature extraction: common encodings (URL, hex, \texttt{CHAR()}/\texttt{ASCII()}) are decoded, SQL keyword casing is normalized, and comment sequences (\texttt{/* */}, \texttt{--}) are \emph{marked as a feature} rather than deleted. The goal is to collapse equivalent syntactic variants so that trivial obfuscation does not change the model's input.

\subsection{Branch 1 - Supervised Multi-Class Classification}
Branch~1 assigns each query to one of six classes: \texttt{normal}, \texttt{union\_based}, \texttt{error\_based}, \texttt{boolean\_blind}, \texttt{time\_blind}, and \texttt{stacked}. We compare four candidate architectures (Section~\ref{sec:results}) and select a fine-tuned DistilBERT classifier for its accuracy on the two hardest classes at a latency that remains real-time-compatible. Multi-class (rather than binary) output lets the decision engine and human administrators reason about \emph{which} attack technique is detected.

\subsection{Branch 2 - Query-Level Anomaly Detection}
Branch~2 is trained on benign traffic only, learning the ``normal region'' of query behavior and emitting a continuous anomaly score per query, from twelve lightweight features: four whole-string statistics (length, special-character ratio, SQL-keyword count, Shannon entropy), a quote-imbalance count, and six ``local-peak'' features (longest same-type token run, max token length, token count, longest special-character run, longest digit run, parenthesis imbalance) chosen so long parameter strings from HTTP-derived sources do not dilute the signal. A global One-Class SVM boundary misclassified benign traffic from one source as anomalous merely for not resembling another's; a per-source ensemble was tried next and rejected for an unacceptably high FPR ($\approx$41\%). LocalOutlierFactor was adopted instead: its local-density notion judges each query against its own neighborhood rather than one global boundary, better accommodating a benign pool spanning structurally distinct sources. Training without attack labels makes the branch, in principle, sensitive to attack shapes never seen by Branch~1, the property probed in the zero-day study; its score also feeds the Session Correlator.

\subsection{Session Correlator (Branch 3) - Session-Level Correlation}
The Session Correlator targets two attack patterns invisible to any query-level branch, since each step looks individually unremarkable: (1) blind SQLi (boolean-blind, time-blind), where an attacker recovers data one bit at a time via a bisection search across many queries, and (2) query-splitting, where a single malicious statement is fragmented across consecutive requests. Our first design, a Gated Recurrent Unit (GRU) consuming Branch~1's classifier output concatenated with Branch~2's anomaly score per step, fails a diagnostic check: two consecutive Boolean-blind bisection steps differing only in comparison bound have TF-IDF cosine similarity 0.961 at the vectorizer stage but near-identical probabilities after Branch~1's classifier, a lossy projection trained to separate attack \emph{type}, not preserve content - the signal a sequence model needs is collapsed before it arrives. We therefore replaced the GRU with the Session Correlator: not a trained model, but two independent checks over the already-trained Branch~1 and Branch~2, OR'd together. The \emph{content check} concatenates a session's raw query text and re-scores it with Branch~1's classifier against a threshold calibrated for session-length text. The \emph{behavior check} aggregates Branch~2's per-query anomaly scores (median, fraction above a calibrated threshold), run exactly as trained, so no train/inference shift is introduced. Both checks are calibrated on a disjoint TRAIN split and evaluated on a held-out TEST split (Section~\ref{sec:results}); each covers cases the other misses, leaving one residual gap by design: an attacker evading both checks simultaneously, which neither branch's signal can close. Because the blind-SQLi session generator bisects toward a fixed target value, its target pool is partitioned into disjoint train and test subsets \emph{before} session generation, so the held-out evaluation measures generalization to unseen targets rather than recall of seen ones.

\vspace{4pt}
Let $S=[q_1, \dots, q_n]$ be a session consisting of $n$ chronologically ordered queries from the same client. Denote\\[2pt]
\mbox{$p(S)=1-P_{B_1}(\text{normal}\mid \Vert_{i} q_i)$} for the concatenated text and \mbox{$s_i=B_2.\text{score}(q_i)$} per query. With calibrated thresholds $\tau_c,\tau_q,\tau_{med},\tau_{frac}$, the checks are defined as:
\begingroup\small
\begin{equation}
\begin{aligned}
fires_c(S)&=\mathbb{I}[p(S)\geq \tau_c],\\
frac(S)&=\frac{1}{n}\sum_{i=1}^{n}\mathbb{I}[s_i>\tau_q],\\
fires_b(S)&=\mathbb{I}[m(S)\geq \tau_{med}] \lor \mathbb{I}[frac(S)\geq \tau_{frac}]
\end{aligned}
\end{equation}
\endgroup
where $m(S)=\mathrm{median}(s_1,\ldots,s_n)$ and the session verdict is\\[4pt]
\mbox{$fires_c(S) \lor fires_b(S)$}. Implemented operationally as in Algorithm~\ref{alg:correlator}.

\begin{algorithm}[htbp]
\footnotesize
\caption{SessionCorrelator: calibration and scoring (no gradient training)}
\label{alg:correlator}
\begin{algorithmic}[1]
\STATE \textbf{Calibration (on TRAIN sessions only):}
\STATE $\tau_q \leftarrow$ 95th percentile of
\STATE \hspace*{1em}$\{B_2.\text{score}(q) \mid q \in \text{benign TRAIN}\}$
\STATE $\tau_c \leftarrow \arg\max_{\tau} (\text{TPR}-\text{FPR})$ on
\STATE \hspace*{1em}$\{\text{concat}(S_{\text{train}}) \text{ scored by } B_1\}$
\STATE $\tau_{med}, \tau_{frac} \leftarrow$ sweep median and fraction-above-$\tau_q$
\STATE \hspace*{1em}on TRAIN
\STATE \textbf{Scoring a session $S=[q_1..q_n]$:}
\STATE $a_c \leftarrow 1-P_{B_1}(\text{normal} \mid \text{concat}(q_1..q_n))$; $fires_c \leftarrow (a_c \geq \tau_c)$
\STATE $scores \leftarrow [B_2.\text{score}(q_i) \; \forall i]$; $m \leftarrow \text{median}(scores)$; $frac \leftarrow |\{s>\tau_q\}|/n$
\STATE $fires_b \leftarrow (m \geq \tau_{med}) \lor (frac \geq \tau_{frac})$
\STATE \textbf{return} $fires_c \lor fires_b$ \COMMENT{content check OR behavior check}
\end{algorithmic}
\end{algorithm}

\subsection{Decision Engine and Overkill Policy}
A central decision engine combines the branch outputs into one verdict (Table~\ref{tab:decision}). Any query classified by Branch~1 as an attack class is \textsc{block}ed. A query classified \texttt{normal} but flagged anomalous by Branch~2 is held as an \emph{Overkill} case: it is not executed and is queued for administrator confirmation, defaulting to \emph{deny} on timeout. Confirmed decisions feed a continual-learning loop (proposed). This policy trades a small amount of friction on rare suspicious-but-benign queries for defense-in-depth against zero-days.

\subsection{Continual-Learning Design}
Confirmed Overkill/Block decisions accumulate into a labeled pool that a continual-learning loop consumes, so the deployed model can improve without full retraining. \emph{Drift monitoring} tracks the Population Stability Index (PSI) of five feature and confidence signals against a fixed reference window, alerting at PSI~$\geq$~0.2, independently of the mechanism below. A \emph{review queue} holds low-confidence and anomalous queries for administrator confirmation; a volume-threshold policy triggers a retrain automatically once confirmed samples cross a fixed count, rather than on a fixed schedule. A \emph{validation gate} then decides whether the candidate may replace the deployed model, distinguishing a \emph{major} bump (the label space changes) from a \emph{minor} one (same labels, more volume): a major bump has no prior model to compare against, so it is checked instead against an absolute floor (no regression on known classes, a minimum recall on the new one) and promoted directly if it clears that floor; a minor bump must match or exceed the current champion's F1/FPR on the frozen benchmark. Only a promoted minor-bump candidate then enters \emph{shadow}, logging predictions against further traffic while the incumbent keeps serving, becoming champion only if shadow-observed FPR and F1 stay within tolerance of the gate-measured values. A major-bump candidate skips shadow, since no incumbent exists for that class and the floor check already carries that weight. Algorithm~\ref{alg:cl} summarizes the loop. Every promotion retires the model it replaces (Shadow~$\rightarrow$~Champion~$\rightarrow$~Retired), with retired models kept for rollback and audit. Section~\ref{sec:results} evaluates this loop as a full offline experiment.


\begin{algorithm}[htbp]
\footnotesize
\caption{Continual-learning loop (offline, Branch 1)}
\label{alg:cl}
\begin{algorithmic}[1]
\WHILE{streaming}
\STATE monitor PSI on 5 signals vs. reference; alert if $\text{PSI} \geq 0.2$
\STATE \hspace*{1em}for 2 sustained windows \COMMENT{drift, does not gate}
\STATE enqueue low-confidence and anomalous queries for admin review
\IF{$|\text{confirmed}| \geq 500$}
\STATE assemble $D' \leftarrow D_{\text{train}} \cup \text{confirmed}$
\STATE \hspace*{1em}(dedup by \texttt{query\_canonical})
\STATE seal data version $v=\text{infer\_bump}(v_{\text{old}}, v_{\text{new}})$
\IF{$v$ is major}
\STATE check floor: no known-class recall drop $>0.02$
\STATE \hspace*{1em}and new-class recall $\geq 0.80$; promote directly if pass
\ELSE
\STATE gate: $F1_{cand} \geq F1_{champ} \land \text{FPR}_{cand} \leq \text{FPR}_{champ}$
\STATE \hspace*{1em}\COMMENT{shadow 2000 queries if pass}
\ENDIF
\ENDIF
\ENDWHILE
\end{algorithmic}
\end{algorithm}

\section{Dataset and Experimental Setup}\label{sec:setup}

\subsection{Data Sources}
Four public datasets are combined: \emph{SQLiV3} (D1, a Kaggle SQLi query collection; license provenance unclear); \emph{CSIC 2010} (D2, HTTP traffic, used for benign enrichment and, held out, as a labeled anomalous set); \emph{Superviz25} (D3, a $\approx$3.69M-row Kaggle dataset of real \texttt{sqlmap} runs against a seeded relational schema; license also unverified); and \emph{SR-BH 2020} (D4, a CC0 honeypot dataset of 527{,}813 rows, 250{,}285 originally tagged \texttt{SQL Injection}) (Section~\ref{sec:discussion}). D4's labels are coarse and multi-attack (Common Attack Pattern Enumeration and Classification (CAPEC)-tagged), so rows are re-tagged into SQLi sub-types by rule-based matching; D3's own \texttt{attack\_technique} column is instead trusted directly, since each row is generated for a known technique against a real database, so its ground truth comes from construction, and a majority are also obfuscated by a real WAF-evasion transform (character-case randomization, whitespace-to-comment substitution) that can break a hand-written regex tagger. Recent SQLi detection papers typically train on tens of thousands to a few hundred thousand rows scraped from Kaggle collections or CSIC 2010 alone \cite{b14,b15}; D3 alone, at $\approx$3.69M rows, is well over an order of magnitude larger, and CSIC 2010, though dated to 2010, remains in active use in 2025 work \cite{b15}, which is why it is retained here alongside newer sources rather than replaced outright.

These four sources are chosen to cover structurally distinct traffic, a claim checked rather than assumed. A leave-one-out ablation retrains Branch~2's benign pool with each source held out in turn, evaluating FPR against every source's own held-out traffic, including the excluded one (Table~\ref{tab:ablation}). Excluding any single source leaves that source's own FPR at 65--80\%, while the other three stay in the 2--7\% range the full model achieves overall, direct evidence that no source is redundant. An earlier pass of this same ablation, which measured FPR only against each reduced combination's own held-out set, had suggested D1 and D2 could be dropped at negligible cost; that conclusion did not survive testing against the excluded sources' own traffic, an artifact of the narrower test rather than a real property of the data, and was not used to guide the final data composition.

\subsection{Branch 1 Dataset}
D3 supplies real \texttt{stacked}-query examples in addition to real examples of the other four attack sub-types (the continual-learning experiment in Section~\ref{sec:results} separately holds out a real class, \texttt{union\_based}, from its own training pool, unrelated to \texttt{stacked}).

Each D3 attack row carries an \texttt{attack\_id} identifying its multi-step \texttt{sqlmap} campaign; rows from the same campaign are near-duplicates, differing mainly in a narrowing bisection bound, so a plain per-row split would leak near-duplicate content across train/test. D3's attack rows are therefore split by whole campaign, every row sharing an \texttt{attack\_id} landing on the same side, while D1/D2/D4 keep the original per-row stratified split. D3's campaigns further split into a \texttt{recon} stage (probing and setup queries, lexically close to legitimate traffic) and an \texttt{exploit} stage (queries carrying the payload); Branch~1 detects \texttt{exploit}-stage rows at 100.0\% but \texttt{recon}-stage rows at only 94.0\%. Because campaign-level splitting means a class's test set can draw disproportionately from a handful of \texttt{recon}-heavy campaigns, per-class recall for the classes D3 dominates (\texttt{stacked}, \texttt{time\_blind}) is sensitive to which campaigns land in the held-out split (Section~\ref{sec:results}).

Content-based signature filtering removes mislabeled attacks from the \texttt{normal} pool over three iterative rounds, and \texttt{query\_canonical} text is deduplicated before splitting, so no query text appears verbatim in both partitions. The final dataset is 90{,}000 rows over six classes (each undersampled to 15{,}000, seed~$=42$), split 71{,}705 train and 18{,}295 test. F1-macro is the headline metric since accuracy would be distorted by class imbalance.

\subsection{Branch 2 Dataset}
Branch~2 pools clean benign rows from all four sources, using a broader content filter that rejects any attack-like traffic. D2 and D4 are captured as full HTTP requests, not raw SQL; since the system consumes only the query/parameter text an application would build (Section~\ref{sec:system}), each such row is stripped to its query-string/body parameters, dropping rows with nothing left after stripping. D3 is already query-shaped, but its benign rows are legitimate multi-table and analytical SQL (joins, sub-queries, geographic functions) against a real schema, structurally unlike the simple parameter lookups the other three sources provide, and, before adding D3's benign traffic, the source of a 69--95\% FPR on this kind of legitimate-but-unfamiliar traffic in a zero-shot check run to decide whether adding D3 was warranted. After filtering, de-duplication, and stripping, the benign pool contains 72{,}162 rows (57{,}321 train and 14{,}841 test); a held-out set of 370{,}002 confirmed-SQLi rows spanning all four sources is used only for evaluation.

\subsection{Session Correlator Dataset}
No public dataset provides session-level SQLi labels, so sessions for the two target scenarios are constructed differently, reflecting how each attack unfolds. Blind-SQLi sessions run the same bisection algorithm real SQLi tools use, length probing followed by per-character ASCII probing ($\sim$7 requests per character), against a real, self-hosted SQLite database, so every probe's outcome is a genuine row-count difference or measured \texttt{SLEEP()} delay, not a templated guess; this is the scenario whose bisection structure exposed the GRU's failure. Query-splitting sessions instead use heuristic token-fragmentation of a single real attack payload across consecutive requests, since no bisection-style search exists for this attack type. Together this yields 1{,}400 sessions across four classes (benign, boolean-blind, time-blind, query-splitting), split 1{,}120 training and 280 test, with the 100-user synthetic target pool itself partitioned into disjoint train/test subsets before sessions are generated. Collecting an independent dataset from real \texttt{sqlmap} traffic against a deliberately vulnerable application is future work (Section~\ref{sec:conclusion}).

\subsection{Evaluation Protocol}
Metric choice follows from each branch's task rather than a single convention across all three. Branch~1 is a multi-class classifier over an imbalanced label set, so F1-macro (not accuracy, which the majority classes would inflate) is the headline metric, alongside per-class precision/recall/F1, a confusion matrix, and per-class ROC to show where errors concentrate. Branch~2 is a one-class anomaly detector with no fixed decision boundary a priori, so we report FPR and detection rate at a specific operating point (the deployment-relevant trade-off), AUC (a threshold-independent summary of ranking quality), and a 21-point threshold sweep to make the trade-off curve, not just one point on it, inspectable. The Session Correlator issues a binary per-class flag from two independently OR'd checks, so FPR on benign sessions and detection rate per attack class are reported separately for each check alone and combined - an ablation, not just a combined number, so neither check's contribution is left unmeasured. All experiments are deterministic (seed~$=42$); latency was measured on a single RTX~3050 (6~GB) workstation.

\section{Experimental Results}\label{sec:results}

\subsection{Branch 1 - Supervised Multi-Class}
Table~\ref{tab:b1arch} compares four candidate architectures on the six-class dataset (Section~\ref{sec:setup}); Logistic Regression and LightGBM use a TF-IDF representation retuned by grid search for this evasion-heavy data (character n-grams (1,2), $C=10$, vocabulary shrunk from 50{,}000 to 5{,}037 terms), while DistilBERT and the CNN use their own tokenizers. DistilBERT reaches the highest F1-macro (0.965), with LightGBM close behind (0.962) at a similar latency (3.0~ms vs.\ 2.8~ms): the smaller TF-IDF vocabulary cut LightGBM's latency by $\approx$20$\times$, removing the reason it was earlier ruled out for a real-time proxy. The CNN tokenizer (0.749) is the weakest candidate, its small (37K-parameter) capacity not holding up against D3's harder, evasion-heavy attack distribution. \subsection{Zero-Day Generalization Study}
To probe robustness to \emph{unseen} attack categories, we run a leave-one-out protocol over five labels (\texttt{normal}, \texttt{union\_based}, \texttt{error\_based}, \texttt{boolean\_blind}, \texttt{time\_blind}): for each attack class, that class is removed and Branch~1 is retrained on the remaining four labels; Branch~2, benign-only and never exposed to attack labels, is not retrained per fold. Table~\ref{tab:zeroday} reports the Branch~1 \emph{miss rate} (fraction predicted \texttt{normal}), the Branch~2 detection rate on the same held-out queries, and their \emph{combined coverage} (caught by at least one branch).

Two findings stand out. First, supervised classification generalizes well to structurally distinctive unseen classes: withholding \texttt{union\_based}, \texttt{error\_based}, or \texttt{time\_blind} still leaves Branch~1 flagging almost all of its queries as \emph{some} attack (miss rate $\leq$2.6\%), and the anomaly branch independently catches nearly all of them too (98.3--99.1\%), since their distinctive structure registers as anomalous regardless of what Branch~1 was trained on. Second, \texttt{boolean\_blind} remains the failure mode, though not as starkly as either branch alone suggests: Branch~1 misclassifies 86.5\% of its queries as \texttt{normal} (Boolean-blind payloads are lexically close to legitimate queries), yet the anomaly branch independently catches 87.8\% on structural grounds alone, and the two combined still leave 11.2\% uncaught, the lowest combined coverage of any class by a wide margin. This residual gap is the empirical motivation for session-level correlation: query-level detection alone still misses roughly one in nine unseen boolean-blind queries. At the session level this same condition closes entirely: the Session Correlator's behavior check, depending only on Branch~2 and thus unaffected by Branch~1's blindness, independently flags all 70 held-out \texttt{boolean\_blind} sessions (Section~\ref{sec:results}), though on a different, self-generated evaluation set, so this is complementary evidence rather than a directly comparable number.

\subsection{Session Correlator}
Table~\ref{tab:b3} reports the mandatory ablation on the 280-session held-out self-hosted test set (disjoint train/test target pools, Section~\ref{sec:system}), recalibrated against the deployed DistilBERT Branch~1: each row runs \emph{only} the named mechanism, except the last, which is how the deployed system runs the two OR'd together. The behavior check's session-level aggregate is each session's \emph{median}, not mean, per-query Branch~2 score: LocalOutlierFactor's score is mathematically unbounded, and a handful of structurally degenerate short queries (from \texttt{query\_splitting} fragmentation) score many orders of magnitude above the rest, which a raw mean let dominate a session's aggregate, pushing benign-session FPR from 0\% to 37\% before this fix (Section~\ref{sec:discussion}).

Content check and Combined (OR) reach zero observed false positives and near-perfect detection on all three attack classes (\texttt{query\_splitting}: 67/70); Behavior check alone does not fully catch \texttt{query\_splitting} (0.386) and, with DistilBERT in place, no longer independently catches \texttt{time\_blind} (0.0, versus 1.0 under the original TF-IDF calibration), both blind spots the content check closes, which is why the checks are OR'd rather than used alone.

\emph{Reading these numbers narrowly.} Zero observed false positives on 70 benign sessions bounds the true FPR only loosely (a 95\% Wilson interval reaches roughly 4\%), and benign sessions are drawn from the same generation process Branch~1 and Branch~2 were built around, not independently-captured production traffic. The disjoint train/test target-pool design (Section~\ref{sec:system}) at least reflects generalization to unseen targets within that process. We read this table as evidence the mechanism works as designed, not yet as evidence of generalization to adversarially-diverse real traffic, which independently-captured attacker traffic (Section~\ref{sec:conclusion}) is intended to test.

\subsection{Continual Learning}
This experiment uses its own dedicated training and replay pool, reused for all three retraining stages (M0/M1/M2), independent of the main Branch~1 pipeline; it runs against the current, DistilBERT-based architecture and data. \texttt{union\_based} is entirely absent from an initial training pool (M0, 28{,}688 rows over the remaining five known classes, including real \texttt{stacked} examples), with a frozen golden set (9{,}000 rows, all six classes, disjoint from anything below) held out for evaluation throughout. A two-pour replay stream follows, padded with real held-out benign traffic from Branch~2's pool: \emph{Scenario~1} interleaves \texttt{union\_based} into ordinary traffic after a quiet head; \emph{Scenario~2} is more volume of the five known classes only, no new class. A review queue and a drift monitor watch both pours independently.

Pre-bump: M0 facing a class it has never seen. On the golden set's five known classes, M0 reaches F1-macro~=~0.9712 (FPR~=~0.0073). On \texttt{union\_based}'s golden rows (n~=~1{,}500, unseen by M0), Branch~1 alone misses 2.1\% (predicts \texttt{normal}); Branch~2, fixed throughout this experiment since it never sees attack labels, independently flags 77.4\%, for 99.5\% combined coverage. (This differs from Table~\ref{tab:zeroday}'s 2.6\%/99.1\%/99.8\% for the same class: that study uses Logistic Regression over the five-label setup above, whereas M0 here is DistilBERT trained on deliberately half of the five known classes' volume, keeping ``half the data, missing one label'' accurate for this experiment's Base.)

The review queue triggers a major bump. As \texttt{union\_based} traffic streams in, flagged occurrences accumulate in the review queue; once 500 confirmed samples are reached (39.9\% through Scenario~1's pour), a retrain triggers automatically. The resulting candidate (M1, 9{,}000 rows) reaches F1-macro~=~0.9711 on the golden set (FPR~=~0.0100) and 98.6\% recall on \texttt{union\_based}, clearing the promotion floor (no known-class regression beyond 0.02 tolerance, new-class recall~$\geq$~0.80); with no prior model to compare against, M1 is promoted directly and M0 is retired. On the remainder of Scenario~1's pour, traffic M1 was never trained on, it independently recalls 98.7\% of the 1{,}484 remaining occurrences, confirming the golden-set number holds on fresh stream data.

Ablation: is the gain from the class, or just from more rows? A control retrains M0's pool with the identical +1{,}753-row budget, resampled entirely from the five known classes, no \texttt{union\_based} at all. The result: 0.000 recall for the control versus 0.986 for M1, on identical row counts. Since row count is held fixed and only composition varies, the gain is attributable to learning the class itself, not to having more training data.

Drift monitoring sees it too, at this concentration. Tracking five PSI signals through Scenario~1 against M0, the flagged-traffic confidence signal crosses the 0.2 alert threshold and is confirmed (two sustained windows) by window~3, the same window the queue's own retrain trigger falls in. This does not overturn a low-concentration negative result reported for a rare ($<$1\%) synthetic class elsewhere in this project's development; at the substantially higher concentration used here, drift and the review queue agree rather than the queue being the only signal that notices.

Scenario 2: a minor bump, correctly rejected. With M1 now champion, Scenario~2 replays known-class volume only, with no new class. Once 500 confirmed samples accumulate (position 2{,}497 of 9{,}049), a class-balanced pool (325 rows, the smallest confirmed class, \texttt{normal} false positives, sets the size) is added and M2 is trained. M2 reaches F1-macro~=~0.9739 on the full golden set, higher than M1, but FPR~=~0.0207, nearly double M1's 0.0100; the zero-slack gate rejects M2 on FPR alone ($0.0207 > 0.0100$), so M1 remains champion and never enters shadow. An F1-only comparison would have promoted M2 instead; the gate's multi-criterion check catches this regression. An earlier run of the same experiment, on a Logistic-Regression-based Branch~1, saw the analogous candidate clear both criteria and reach shadow; we report this run's actual outcome rather than that one, consistent with this project's practice of not re-rolling a result to fit an expected story (Section~\ref{sec:discussion}).

Replayed against M1, Scenario~2's drift signals stay flat throughout, confirming the expected contrast: ordinary volume growth alone does not look like drift.

\emph{Reading these numbers narrowly.} Both pours are padded with real benign traffic, but at a higher attack concentration than production would see. Labelling is simulated (ground truth stands in for a human reviewer), and traffic is a replay of held-out data, not live production traffic. The review queue and validation gate are implemented and tested as a library, but production wiring into the deployed service is not yet complete for all branches, so this offline result validates the mechanism, not a running deployment. Because M2 was rejected before reaching shadow, this run does not exercise the shadow-validation path for a promoted minor bump; that path is covered by this project's own library tests, not by this specific run.

\subsection{Latency Budget}
End-to-end per-query latency is estimated from measured per-branch costs, not benchmarked under load on the live service. Branch~1 (DistilBERT) inference is 2.8~ms on GPU (Table~\ref{tab:b1arch}). Branch~2's LocalOutlierFactor scores each query against its stored training set (a $k$-nearest-neighbor lookup, not a fixed boundary like One-Class SVM), costing substantially more than a linear model: $\approx$15--18~ms per query, measured on the same workstation. Decision-engine logic is negligible. The combined budget is therefore $\approx$18--21~ms per query, dominated by Branch~2, still compatible with a real-time proxy but one this offline figure should be re-measured against the live \texttt{/api/v1/detect} endpoint before being treated as a deployment guarantee, particularly since Branch~1's GPU dependency is a new cost Logistic Regression did not carry. Sustained-throughput benchmarking is left to future work.

\section{Discussion and Limitations}\label{sec:discussion}
Label noise. Two measured noise sources are found during data construction: mislabeled attacks in the D4 \texttt{normal} pool (requiring three rounds of content filtering) and $\approx$13\% mislabels in the \texttt{boolean\_blind} catch-all class (30-sample manual audit, a small sample). Both remain real, secondary contributors to Table~\ref{tab:b1perclass}'s errors, but the dominant confusion (\texttt{stacked}$\leftrightarrow$\texttt{time\_blind}) is explained separately in Section~\ref{sec:results} by D3's recon/exploit campaign structure; the clean-label ceiling for this task is unknown.

Dataset licensing. D4 (CC0) has a confirmed license; D1 (SQLiV3) and D3 (Superviz25) both lack an explicit license; D2 (CSIC 2010)'s license was not independently re-verified for this revision. The combined dataset should be treated as provenance-unclear pending resolution.

Threat-model and robustness boundaries. Second-order and out-of-band SQLi, and non-SQL web attacks (Cross-Site Scripting (XSS), Cross-Site Request Forgery (CSRF)), are out of scope by the proxy placement. All results are on clean test splits; no adversarial evaluation (e.g.\ WAF-A-MoLE \cite{b11}) was run, so the reported figures are an upper bound on robustness to deliberate evasion.

LocalOutlierFactor's costs. Unlike a fixed-boundary model (One-Class SVM, Isolation Forest), LocalOutlierFactor retains its full training feature matrix and scores each query via a $k$-nearest-neighbor lookup, giving a larger artifact and higher latency (Section~\ref{sec:results}) in exchange for its higher detection rate. Its raw anomaly score is also mathematically unbounded (scores in the billions on a handful of structurally degenerate short queries, versus under 15 for the other two algorithms); this leaves Table~\ref{tab:b2}'s threshold- and rank-based metrics unaffected, but once silently broke the Session Correlator's behavior check, whose mean-based aggregate a single such outlier could dominate, pushing benign-session FPR from 0\% to 37\% before switching the aggregate to the median (Section~\ref{sec:results}).

The continual-learning gate's zero FPR slack. The minor-bump path (Section~\ref{sec:results}) requires no FPR regression at all against the champion, unlike the separate shadow-stage tolerance applied only after a candidate has already passed the gate; this is a stricter bar than an F1-only comparison would apply, and one sensitive to how precisely FPR is estimated on a finite golden set.

Session Correlator operational scope. The single-query endpoint currently invokes the Session Correlator with only that one query as a degenerate one-step session; realizing session-level correlation across separate requests over time requires a session store (keyed by session/IP with a TTL) that has not yet been built. The dedicated session endpoint, evaluated in Section~\ref{sec:results}, already accepts a complete session's queries in one call.

\section{Conclusion and Future Work}\label{sec:conclusion}
We presented a multi-branch AI system for SQLi detection at the database proxy, combining a supervised six-class classifier (Branch~1, DistilBERT, F1-macro~=~0.9699) with a benign-only anomaly detector (Branch~2, LocalOutlierFactor, AUC~=~0.915, 78.4\% detection at 5.3\% FPR) over four public datasets, each shown individually necessary by a leave-one-out ablation (Table~\ref{tab:ablation}). A leave-one-out zero-day study shows supervised detection stays robust for structurally distinctive unseen attacks but bypasses boolean-blind SQLi at an 87\% rate, with the two branches combined still leaving an 11\% residual gap; this ceiling on query-level detection motivates the Session Correlator, which re-uses both branches' existing signals with no additional training and reaches zero observed false positives with near-perfect detection (95.7--100\%) on held-out self-generated sessions, not yet validated on independently-captured attacker traffic. An offline continual-learning loop, evaluated using a real held-out attack class, shows a review queue and drift monitoring both surfacing the new class, automatic volume-triggered retraining, a validation gate promoting the resulting major-bump model after an absolute-floor check, and the same gate correctly rejecting a subsequent minor-bump candidate with higher F1 but higher FPR, evidence the gate weighs more than a single metric.

Future work centers on validating the Session Correlator against real \texttt{sqlmap} traffic from a network-isolated vulnerable lab (DVWA/WebGoat), captured via an intermediate proxy, rather than self-generated sessions. Further items include a production session store for incremental cross-request correlation, wiring the review queue and drift dashboard into the deployed service for all branches, adversarial hardening, and re-measuring latency and throughput against the live endpoint under realistic load.
